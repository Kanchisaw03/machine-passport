# Assumptions and implementation notes

- The first increment favors a runnable local demonstration over full cloud/AI scope. SQLite and the local filesystem are the only implemented storage backend.
- Machine metadata, audio clips, baselines, telemetry, technician notes, recommendations, events, outcomes, and audit records are stored in SQLite. WAV audio is normalized to mono PCM16 when saved.
- REAL denotes app-recorded or externally ingested data; it does not imply calibrated industrial instrumentation. SIMULATED and SEEDED are reserved provenance values; the public demo machine is seeded idempotently at startup.
- The robust feature set uses RMS, crest factor, kurtosis, zero-crossing rate, spectral centroid/bandwidth/rolloff/flatness, four fixed bands, spectral peaks, an envelope spectrum, and downsampled Welch PSD. The current scorer includes the named scalar feature subset.
- Baseline calibration uses the 95th percentile of leave-one-out healthy scores, with a minimum threshold of 1.0. The public fan teaching subset showed that an additional 1.25 margin cut recall from 10/20 to 5/20 at the observed zero false-positive point; the no-margin operating point is used by default and is not a statistically validated false-alarm guarantee.
- WATCH/ALERT boundaries are threshold and 1.5 times threshold. They are simple review labels and must not be interpreted as failure probabilities.
- Voice notes retain their original audio, use Gemini audio understanding for transcript/translation/structured fields when configured, and use local hashed term-frequency vectors with IDF-weighted cosine similarity for retrieval. Audio-derived notes require technician confirmation before they can support recommendations. The real Gemini path has not yet been exercised without an API key/project.
- Recommendations use a provider interface with deterministic mock, Gemini Developer API/Vertex AI, and best-effort local Ollama implementations. Gemini is the default only when credentials are present; otherwise deterministic mock output is explicitly labelled as a template. Current official docs list `gemini-3.8-flash` and `gemini-embedding-2`; verify the model catalog before future releases.
- Provider prompts contain only retrieved machine evidence/current state and explicitly treat note text as untrusted data. The server removes unknown evidence IDs and flags numeric claims that do not appear among evidence values; invalid output falls back to a deterministic evidence template.
- Dense `gemini-embedding-2` vectors are stored when Gemini embedding succeeds. When credentials are absent or embedding fails, note retrieval uses a stored local hashed TF-IDF-style vector and reports that mode. Dense embeddings are therefore not present for every note.
- Gemini raw response text is stored in the SQLite knowledge/recommendation rows; its SHA-256 is included in the audit-chain payload. Raw response text is omitted from ordinary machine API responses.
- Modification decisions preserve the original recommendation and append the operator edit to its content for traceability.
- Authentication is omitted; the operator name is a local browser preference only in future work. Current actions use a default `Operator` label.
- Browser service-worker caching is implemented for app-shell GET requests. Offline recording and upload queuing are not implemented.
- QR codes point to `PUBLIC_BASE_URL` (default localhost). Phone microphone capture over a network requires a trusted HTTPS origin.
- Evaluation repeats 30 seeded train/test splits by default; its healthy-only threshold rule and limitations are documented in docs/CALIBRATION.md. Current evidence is one small public fan subset only; no pump or own-machine evidence is available.
- Uploads accept 16, 22.05, 44.1 and 48 kHz PCM WAV, then resample to 16 kHz for analysis. The broadband-noise gate uses spectral flatness as a heuristic; it has not been validated against calibrated background-noise measurements. `scripts/compare_device_wavs.py` compares two recordings believed to be the same source, but cannot establish that they are equivalent.
- Public Cloud Run uses one instance because SQLite and per-instance request limiting are local. The Gemini quota uses Firestore transactions when the Cloud Run runtime identity can access Firestore; this requires the Firestore API/database and IAM grant. Uploaded WAV and machine records remain ephemeral. The cleanup task removes old non-seeded machines, and owner deletion removes user-created machine data.
- Public demo ingress permits anonymous access and must only receive demo data. Feedback suggestions can contain free text; export requires `FEEDBACK_ADMIN_TOKEN`. Feedback counts are omitted until feedback exists.
- When `GCS_BUCKET` is set, audio files are written to private `gs://` objects and each committed audit action stores an online SQLite backup in `database/machine_passport.sqlite3`; a cold start restores that backup if no local DB exists. GCS permission failures fail the configured storage operation. Without the variable, local ephemeral files remain the backend.
- `PUBSUB_AUDIT_TOPIC` optionally publishes versioned audit events; `scripts/consume_pubsub_telemetry.py` pulls `machine_passport.telemetry.v1` messages and applies the same telemetry validation. Pub/Sub delivery is at least once; the consumer records message IDs transactionally with telemetry so redelivery does not duplicate samples. Neither path is active unless configured.
- The browser DeviceMotion capture records timestamped x/y/z acceleration including gravity as REAL telemetry after an explicit button press and browser permission. It is a raw phone-motion stream, not calibrated industrial vibration instrumentation.
- Ollama uses a schema-constrained `/api/generate` request and passes output through the same evidence grounding validator as Gemini. Automated tests use a mocked local endpoint; live inference still requires a reachable Ollama service/model.
- REAL customer validation, live Gemini calls, a configured Cloud Run Gemini secret, Firestore quota permissions, live GCS durability, live Pub/Sub, live Ollama inference, and physical sensor capture remain unverified until credentials/configuration or hardware are supplied and the relevant checks are performed.
